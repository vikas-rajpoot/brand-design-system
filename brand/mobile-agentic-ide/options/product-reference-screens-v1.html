Reference screens for MobileAgenticIDE

Choose the neutral screen set that should remain fixed while later brand systems are compared. The choice locks tasks, states, sample content, and viewports—not the final UX or visual style.

Concept fixtures only. Nothing shown here is a live or verified product capability. All screens use grayscale, system type, and functional shapes on purpose.

Option A · Balanced · 5 screens

Core work loop

A compact fixture covering connection, active work, a consequential approval, code review, and reconnection. This is the smallest set that still exercises the product’s central promise.

Pros

  • Fast to review repeatedly
  • Balanced product coverage
  • Strong test of UI hierarchy

Cons

  • Setup depth is limited
  • No empty or hard-error state
  • Hosted mode stays deferred

Option B · Safety emphasis · 6 screens

Trust and recovery

A fixture centered on connection identity, permission scope, stale approvals, interruption, and honest recovery. It makes the hardest product boundaries visible early.

Pros

  • Strongest trust coverage
  • Tests warnings without color
  • Exposes recovery semantics

Cons

  • Less emphasis on routine flow
  • Heavier review burden
  • Could over-weight edge states

Option C · Comprehensive · 7 screens

End-to-end product slice

A broader fixture from first connection through work, review, interruption, and completion. It provides the richest base for later app, component, and marketing previews.

Pros

  • Best end-to-end coverage
  • Includes empty and completed states
  • Useful across more later systems

Cons

  • Largest fixture to maintain
  • More screens per design review
  • May dilute focus on risk states
