Decision gate 00 · v3 · runtime platform

One mobile IDE. Every agent. Any workspace.

MobileAgenticIDE can run its own agent harness or connect to Claude CLI, Codex, GitHub Copilot, and future runtimes. The same mobile workspace reaches your laptop, VPS, or managed Vercel Sandbox.

Product architecture: the phone is the IDE surface; the runtime adapter and workspace determine where work executes. Direct laptop/VPS connections and managed sandbox sessions are explicit, inspectable modes.
Direction A

Mobile IDE

Make the category unmistakable: serious software development from a phone.

Cohesion

Premium native utility, editor-grade typography, fast navigation, and clear boundaries between code, agent intent, and execution.

Pros

  • Strongest category and clearest user understanding.
  • Gives the product permission to support editing, testing, review, and shipping.

Cons

  • Creates a high expectation for IDE depth on mobile.
  • Agent integrations become supporting infrastructure rather than the headline.
Direction B

Agent Control Plane

Make runtime choice and workspace portability the central product idea.

Cohesion

Structured, capability-aware, and trustworthy. Runtime adapters, workspace identity, permissions, and resilience become the visual language.

Pros

  • Strongest long-term moat and extensibility story.
  • Supports the own harness plus Claude CLI, Codex, Copilot, and future integrations honestly.

Cons

  • More technical and less instantly legible in the App Store.
  • Requires clear capability differences between adapters.
Direction C

Build From Anywhere

Lead with the outcome: the work follows the developer, not the machine.

Cohesion

More human and outcome-led, with clear progress, calm motion, and a direct promise of freedom without abandoning control.

Pros

  • Best emotional hook for developers who want to leave the desk.
  • Works across laptop, VPS, and sandbox without leading with infrastructure.

Cons

  • Can sound like a productivity wrapper if the IDE depth is not visible.
  • Needs careful language around deployment and hosted environments.
